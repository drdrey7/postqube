# Contributing to Postqube

Target the postqube branch. Describe the user problem and scope, keep patches small,
include meaningful validation and document source/license changes. Update screenshots
only using an empty disposable workspace. Do not publish or schedule real posts in
tests. UI changes should preserve accessibility and mobile layouts.

Postqube contributions are offered under the same AGPL terms as the covered work.
Contributors must have rights to what they submit. An upstream Postiz CLA is not
automatically a Postqube CLA; original files are retained for provenance only.
